Дни зарплаты

День зп — число месяца, до которого учитываются часы (отсечка периода). По умолчанию деньги приходят в этот же день. Если на практике приход денег сдвигается и меняется по месяцам (то 5-е, то 10-е) — отметь конкретные даты ниже в «Фактических датах выплат». Не настроено — доход начисляется ежедневно (как раньше).

Фактические даты выплат

Каждый месяц день прихода денег может быть свой (то 5-е, то 10-е). Отметь две даты: день выплаты — когда деньги пришли (или придут) на карту; день учёта часов — до какого дня они посчитаны (необязательно, пусто = по дню зп). Пара заменяет запланированную выплату того месяца. Дату выплаты можно ставить и в будущем (если знаешь, что зп придёт позже). Не отмеченные месяцы — по дню зп.

Чекпоинты баланса

Самый поздний фактический чекпоинт — стартовая точка прогноза. Будущие фактические чекпоинты калибруют прогноз. Целевые чекпоинты — это твои хотелки: они показываются маркером на графике, но не двигают траекторию.

Сохранение

Данные хранятся в браузере автоматически. Для переноса на другой компьютер — экспортируй в файл.

Синхронизация (GitHub Gist)

Хранит твоё состояние в приватном gist на GitHub — синхронизация между устройствами без своего бэкенда. Авто-push через ~5 сек после изменения, авто-pull при возврате на вкладку.

📖 Инструкция — как настроить

1. Создай Personal Access Token на GitHub.

  • Открой github.com/settings/tokens → Generate new token (classic).
  • Название — любое («clockifyAnalyzer sync»). Expiration — на год или No expiration.
  • Отметь только scope gist. Остальное не нужно.
  • Нажми Generate token и скопируй его (он показывается один раз).
  • Альтернатива — Fine-grained token: Account permissions → Gists: Read and write.

2. На первом устройстве (откуда переносишь данные):

  • Вставь токен в поле Personal Access Token ниже.
  • Нажми «➕ Создать новый gist», подтверди — создастся приватный gist с текущим состоянием.
  • В статусе появится Gist: abc123... со ссылкой. Скопируй ID (или просто URL — пригодится на втором устройстве).

3. На втором устройстве:

  • Создай ещё один токен (или используй тот же — но лучше отдельный для каждого устройства, чтобы можно было индивидуально отозвать).
  • Вставь токен в поле ниже.
  • Вставь Gist ID или URL с первого устройства в поле Gist ID или URL.
  • Нажми «🔗 Связать (pull)», подтверди затирание локальных данных.

4. Дальше работает само. Локальные изменения улетают в gist через ~5 сек после паузы в правках. При переключении на вкладку (или возврате с другого устройства) свежие данные подтягиваются автоматически. Кнопки Push / Pull — на случай ручной операции или если статус говорит про конфликт.

Если что-то пошло не так:

  • «Неверный токен» — токен истёк, без scope gist, или скопирован с пробелом.
  • «Gist не найден» — опечатка в ID, gist удалили, или токен из другого аккаунта.
  • «В gist нет файла finance_state.json» — кто-то редактировал gist вручную и сломал. Сделай Push с рабочего устройства, чтобы перезаписать.
  • Конфликт-тост «есть свежие данные + локальные изменения» — реши вручную: Push (отправить локальное в gist) или Pull (взять из gist, потерять локальные).

Безопасность. Токен лежит только в localStorage этого браузера и шлётся исключительно на api.github.com. Данные в gist хранятся в открытом виде, поэтому держи gist приватным. Если боишься утечки — отзови токен на github.com/settings/tokens, сам gist это не затронет.

Фактические расходы по чекпоинтам

Считается из того, как реально менялся баланс между двумя соседними фактическими чекпоинтами: заработано + поступления − Δбаланса. Это весь cash-out, включая то, что не внесено в список расходов. Кнопка × рядом со строкой исключает интервал из расчёта (например, разовая большая покупка, отпуск). Прогноз использует устойчивую оценку (последние 90 дн., или винзоризованное среднее) — она же показана внизу.

Прогноз накоплений

Будущий доход моделируется блоковым бутстрапом по полным неделям из истории Clockify (свежие недели весят больше, T½ настраивается в «Параметрах») × ставка × (1 − налог). Из баланса вычитаются введённые расходы (с учётом годового роста) и фоновый авто-расход, оценённый по чекпоинтам с устойчивой статистикой. Отпуска не приносят дохода. Формулы и допущения

История Clockify взвешивается по свежести с периодом полураспада T½ дней (настраивается в «Параметрах», по умолчанию 60): вес дня = 2^(−дней_назад / T½), отсчитывается от today(). Меньше T½ — модель реагирует быстрее, больше — стабильнее.

Дни, отмеченные как отпуск/нерабочие, полностью исключаются из исторических расчётов и из прогноза (доход в них не начисляется).

По взвешенной истории для каждого дня недели w ∈ {Пн…Вс} считается:

  • p_work[w] — взвешенная доля дней этого недельного дня, в которые была работа
  • pool[w] — массив фактических часов в такие дни (каждый отсчёт с собственным весом по свежести)
  • avg_h[w] — взвешенное среднее часов в рабочий день этого типа
  • E[h][w] = p_work[w] · avg_h[w] — ожидаемое число часов в день недели w

Симуляция на горизонте прогноза (Monte Carlo, 5000 запусков) — блоковый бутстрап по неделям:

  • Каждая прогнозируемая неделя сэмплирует из истории целую неделю Пн–Вс как единый блок — сохраняет корреляцию «загруженных» и «расслабленных» недель
  • В историю попадают только полностью покрытые недели (Пн–Вс внутри диапазона данных) — частичные недели на границах больше не дают «фейковых нулей»
  • Позиция недели в месяце (1-я…5-я) берётся от понедельника — теперь совпадает с историческими WoM, даже если прогноз стартует в середине недели
  • Если такая WoM есть ≥2 раз в истории — выбор только из них; иначе — из всех
  • Вероятность выбрать конкретную историческую неделю пропорциональна её весу свежести
  • Если истории меньше 8 полных недель — fallback: независимая выборка по каждому дню с теми же весами свежести
  • Доход за работу: часы × ставка × (1 − налог)
  • Расходы с заданным годовым ростом индексируются по формуле amount · (1+rate)^(лет от сегодня) — учитывает индексацию ренты и подписок

Авто-расход по чекпоинтам. На каждый межчекпоинтный интервал считается ставка имплицитного оттока (заработано + поступления − Δбаланс − введ. расх.)/дней · 30.44. Используется устойчивая оценка:

  • Если есть данные за последние 90 дней — среднее за окно 90 дн.
  • Иначе при ≥4 интервалах — винзоризованное среднее (отбрасываем по одному выбросу с каждого края), чтобы один разовый интервал не перекосил оценку
  • Иначе — простое среднее
  • Каждая симуляция Монте-Карло берёт свою ставку из эмпирического распределения интервалов (с центрированием на оценочное среднее) — это даёт прогнозу честный разброс по неопределённости трат

Интервалы, помеченные как «исключённые» в таблице фактических расходов, не учитываются в авто-оценке (полезно для разовых больших покупок).

Чекпоинты делятся на фактические и целевые. Фактические — это то, что было реально. Целевые — это твои хотелки. Калибровка работает только по фактическим:

shift += B_actual − (mean[i] + shift)

Целевые показываются маркером, но не двигают траекторию.
