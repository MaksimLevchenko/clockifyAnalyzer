# Денежный горизонт

Статическое веб-приложение, которое показывает текущий баланс, ближайшую зарплату, невыплаченный заработок и три сценария накоплений. История работы загружается из Clockify, денежные события задаются вручную. Приложение работает без сборки и собственного бэкенда: состояние хранится в браузере, а синхронизацию через GitHub Gist можно включить отдельно.

**Открыть приложение:** [maksimlevchenko.github.io/clockifyAnalyzer](https://maksimlevchenko.github.io/clockifyAnalyzer/)

## Возможности

### Работа и данные Clockify

- Импорт Detailed report в CSV или PDF с полной заменой рабочих записей.
- Догрузка новых отчётов без точных дублей. Изменённые записи со сдвинутым временем распознаются и заменяют старую версию; отсутствующие в новом файле локальные записи сохраняются с предупреждением.
- Ручное добавление, редактирование и удаление записей.
- Групповые операции по диапазону дат, проекту и дням недели: изменение ставки или часов, масштабирование часов и удаление.
- Временная шкала моделей дохода: переходы между почасовым доходом и окладом либо изменение параметров того же типа с выбранной даты.
- Для каждой версии отдельно задаются ставка или месячный оклад, реактивность прогноза, налог и дни выплат. Оклад можно распределить по дням фиксированными суммами или процентами.
- Валюта остаётся общей для всей истории. Налог показывается справочно и не вычитается из прогнозного баланса.

### Денежная модель

- Расходы трёх типов: ежемесячные, равномерно распределённые по дням месяца и разовые.
- Расход задаётся фиксированной суммой или процентом от выплаты, месячного дохода либо баланса.
- Регулярное правило можно остановить с выбранной даты, сохранив прошлые списания, либо удалить вместе со всем его влиянием.
- Годовая индексация регулярных расходов.
- Разовые поступления: премии, возвраты и другие пополнения.
- Отпуска и другие нерабочие периоды, исключаемые из исторической загрузки и будущего дохода.
- До четырёх дней зарплаты в месяц и отдельные фактические даты выплаты/учёта часов.
- День учёта часов можно зафиксировать до того, как станет известна фактическая дата выплаты;
  такой заработок показывается как ожидающий и не увеличивает баланс.
- Фактические и целевые чекпоинты баланса.
- Расчёт реального денежного оттока между фактическими чекпоинтами, включая не внесённые вручную расходы. Нетипичные интервалы можно исключать из автооценки.

### Аналитика

- Доход и часы по дням, доход по месяцам и накопительный доход.
- Доход по проектам и дням недели, распределение дохода за рабочий день.
- Помесячная таблица часов, дохода и числа рабочих дней.
- История фактического баланса по чекпоинтам.
- Помесячный прогноз дохода и распределение финального баланса.

### Прогноз накоплений

- 5000 воспроизводимых Monte Carlo-симуляций.
- Блоковый бутстрап по полным неделям Clockify с большим весом свежей истории; при короткой истории используется подневная модель.
- Учёт графика выплат, невыплаченной работы, расходов с индексацией, разовых поступлений, нерабочих периодов и фонового оттока по чекпоинтам.
- Калибровка по будущим фактическим чекпоинтам и оценка вероятности достижения целевых.
- Средний, медианный, лучший и худший сценарии, интервал 80%, вероятность отрицательного баланса в конце и кассового разрыва внутри периода.
- Оценка доходов и расходов в месяц, запаса прочности, безубыточного дохода, ближайшей зарплаты и уже заработанной, но ещё не выплаченной суммы.
- Интерактивный график: готовые периоды, масштабирование кнопками, колесом или щипком, прокрутка перетаскиванием и переход к сегодняшней дате.
- Фильтруемые маркеры расходов, пополнений, выплат, дат учёта часов, чекпоинтов, целей и нерабочих дней.

## Быстрый старт

### Онлайн

Открой [опубликованную версию](https://maksimlevchenko.github.io/clockifyAnalyzer/) в современном браузере.

### Локально

Сборка и установка зависимостей не нужны:

```shell
git clone https://github.com/MaksimLevchenko/clockifyAnalyzer.git
cd clockifyAnalyzer
```

После этого открой `index.html` двойным кликом или командой:

```shell
start index.html       # Windows
open index.html        # macOS
xdg-open index.html    # Linux
```

## Первый расчёт

1. На вкладке **«Данные»** импортируй CSV/PDF Detailed report из Clockify.
2. Там же добавь хотя бы один фактический баланс.
3. В **«Настройках»** проверь базовую модель или добавь переход на новую ставку либо оклад.
4. На вкладке **«План»** добавь расходы, поступления и нерабочие периоды.
5. Вернись в **«Горизонт»**, выбери дату и нажми **«Пересчитать»**.

По умолчанию горизонт заканчивается через 90 дней после якорного чекпоинта. Якорь можно выбрать вручную из фактических чекпоинтов.

## Импорт отчётов Clockify

- **«Импорт (заменить)»** заменяет только рабочие записи. Остальные настройки, расходы, поступления и чекпоинты сохраняются.
- **«Догрузить (без дублей)»** объединяет новый отчёт с текущими данными и подходит для регулярного обновления истории.
- CSV должен соответствовать стандартному Detailed report Clockify и содержать как минимум дату начала и длительность в десятичном формате.
- PDF разбирается локально в браузере. Для первого PDF-импорта требуется интернет, чтобы загрузить PDF.js.

### Сбор нескольких месяцев в один CSV

В репозитории есть [userscript для Clockify](clockify-detailed-report-export.user.js). Он добавляет на страницу Detailed report панель, последовательно собирает выбранные месяцы, удаляет дубли и скачивает единый совместимый CSV.

Для использования добавь файл в менеджер userscript-скриптов, открой Clockify Detailed report, укажи диапазон месяцев и нажми **«Собрать CSV»**.

## Хранение и синхронизация

- Состояние автоматически сохраняется в `localStorage`.
- Резервную копию финансового состояния можно выгрузить в `finance_state.json` и затем импортировать на другом устройстве.
- Опциональная синхронизация хранит тот же JSON в приватном GitHub Gist.
- После настройки Gist локальные изменения автоматически отправляются примерно через 5 секунд, а свежая версия проверяется при возврате в приложение.
- При одновременных локальных и удалённых изменениях приложение не перезаписывает их автоматически и предлагает выбрать Push или Pull.

Для Gist нужен GitHub Personal Access Token только с разрешением `gist`. Токен хранится в `localStorage` текущего браузера; отключение синхронизации удаляет локальный токен и связь, но не сам gist.

## Как устроен прогноз

Прогноз строится от последнего фактического чекпоинта или от выбранного пользователем якоря. Свежесть истории регулируется параметром `T½`: маленькое значение быстрее реагирует на изменения загрузки, большое сильнее сглаживает их.

Почасовая версия использует рабочие часы и собственную ставку. Если настроены дни зарплаты, заработок сначала накапливается как невыплаченный и попадает в баланс в дату выплаты; без дней выплаты доход начисляется ежедневно. Окладная версия игнорирует часы при расчёте денег и создаёт фиксированные выплаты по своему расписанию. При переходе старая версия заканчивается накануне, поэтому прошлые расчёты не меняются.

Процент ежедневного расхода считается месячной суммой и равномерно распределяется по календарным дням. Ежемесячное процентное правило списывает весь процент в выбранный день, разовое — в указанную дату.

Фактические чекпоинты используются для восстановления прошлого баланса, оценки фоновых расходов и калибровки будущей траектории. Целевые чекпоинты не меняют прогноз — для них рассчитывается вероятность достижения.

## Деплой на GitHub Pages

1. Открой **Settings → Pages** в репозитории.
2. Выбери **Deploy from a branch**, ветку `main` и папку `/ (root)`.
3. Сохрани настройки. Последующие push в `main` будут обновлять опубликованную версию.

## Приватность и внешние запросы

По умолчанию отчёты, часы, ставки и балансы остаются в браузере. Выбранные CSV/PDF-файлы не загружаются на сервер приложения.

Сетевые запросы используются для:

- загрузки Google Fonts;
- загрузки PDF.js с CDN при импорте PDF;
- обращения к `api.github.com`, только если включена Gist-синхронизация.

При включённой синхронизации финансовое состояние хранится в gist как обычный JSON, без прикладного шифрования. Не делай gist публичным и отзывай токен, если устройство или токен могли быть скомпрометированы.
